# On-Demand Learning — the just-in-time ledger

**What this is:** The open track for anything you need to learn that *isn't* on a curated roadmap — usually **work throws something new at you and you need it now**, before you can use it or add it to a system. You name the topic; `/learn new <topic>` researches it live, teaches it at the right tier tied to your real situation, and **banks it here so it's never lost.** Learn-before-you-add, captured.

**How it differs from `ai` / `py` / `soft`:** those are curated roadmaps (pre-listed `[ ]` units, walked top-down). This one has **no roadmap — the unit is whatever you bring.** This file is an *index of what's been learned on demand*, newest first — a ledger, not a plan.

**Graduation:** when a topic recurs or grows into a real body of knowledge, graduate it into its own full track (the way soft-skills became one on 2026-07-07). `/learn new` will offer that when a cluster starts forming here.

**The flow (same rigor as every `/learn`):** research-first → prior-knowledge probe → teach at the tier bar, tied to your real work → explain-back → **build-before-bank** → logged here.
- **Technical / code topic** → gets a worksheet in `career/lesson_assignments/` (named `YYYY-MM-DD_<kebab-topic>.py`) **and** may enter `career/concept_queue.md` for a later `/sharpen` cold-defense, if it's worth owning at teach-it depth.
- **Conceptual / non-code topic** → no worksheet; banked by *using* it (a real application), like the `soft` track.

**Tiers (same standard):** Tier 1 = mechanism + why-this-over-that + failure mode (teach-it). Tier 2 = decision-level (when to reach for it + the one-line why). The topic's tier is set at the top of each session based on how deep the work actually needs it.
