## What was taught — 1.1 ASGI vs WSGI `[B]`

**Live research (Rule 1):**
- [FastAPI — Concurrency and async/await](https://fastapi.tiangolo.com/async/) — confirms plain `def` handlers run "in an external threadpool that is then awaited." **Notably silent on the threadpool's size limit** — the doc gives the rule without the failure mode.
- [FastAPI — Server Workers](https://fastapi.tiangolo.com/deployment/server-workers/) — **current guidance verified live.** `fastapi run --workers N` / `uvicorn --workers N` is the recommended multi-worker form, and the page **no longer mentions gunicorn at all**. Verbatim: *"when running on Kubernetes you will probably not want to use workers and instead run a single Uvicorn process per container."*

**Deprecated pattern named:** `gunicorn -k uvicorn.workers.UvicornWorker` is the recipe in most 2022–2024 tutorials and is absent from the current docs. Same-family correction: on **ECS Fargate**, leave workers at 1 and scale via ECS desired count.

**The teaching, in order:**
1. Both are **specifications** — a signature plus a protocol — not packages. WSGI: called once, returns once. ASGI: called once, then `receive`/`send` many times until that connection closes.
2. The concurrency model is the actual `[B]` answer: WSGI's unit of concurrency is an **OS thread** (~8 MB stack + kernel scheduler entry); ASGI's is a **coroutine object on the heap** (hundreds of bytes to a few KB). Same bytes on the wire — radically different cost to *wait*.
3. **Why this JD says "high-performance and asynchronous" in one breath:** a resource server is near-100% waiting (JWKS, Postgres, downstream calls) and near-0% computing. Textbook event-loop workload.
4. The honest inverse: ASGI buys nothing on CPU-bound work, and done wrong is **strictly worse** than WSGI.
5. Worker topology + the container rule (above).

**Taught beyond the unit, in response to his questions** (all foundational, all load-bearing):
- Listening socket vs connection socket; `101 Switching Protocols` for WebSocket upgrade; SSE as "never finish the body."
- `epoll`/`kqueue` — the process sleeps and the *kernel* wakes it. This is the missing half of why coroutines are cheap: a waiting thread is also asleep, but you paid 8 MB to hold its place.
- Stack vs heap, corrected off "heap = stack-like with fast lookups."
- `await` = suspend point; `asyncio.gather`/`TaskGroup` = concurrency within one request.
