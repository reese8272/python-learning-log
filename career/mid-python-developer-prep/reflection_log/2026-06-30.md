## Taught (live-researched, current pattern only)

**1. Runtime truth.** Hints are inert metadata in `__annotations__`; three consumers read them — static checkers, humans, and opt-in runtime frameworks (Pydantic/FastAPI). The interpreter never checks.

**2. Nullable ≠ Required (the core correction).** Two independent axes:
- nullable = the **type** → `int | None` (value may be None)
- required = the **default** → no default = required; `= None` = optional
Four corners: `int` (req, not-null) · `int | None` (req, nullable) · `int = 0` (opt, not-null) · `int | None = None` (opt, nullable). `Optional[int]` means *exactly* `int | None` and says nothing about required. Python docs quote, verbatim: *"this is not the same concept as an optional argument, which is one that has a default."*

**3. Pydantic v2 / FastAPI tie-in (why Tier 1).** Same rule governs request fields: `variable: str | None` → **required**, omitting it = **422**; `level: str | None = None` → optional.
- ⚠ **Currency:** Pydantic **v1** made `Optional[x]` implicitly default to None (treated nullable as optional). **v2 removed that** — `x: int | None` is required. Same staleness class as `.dict()`→`.model_dump()`. A 2022 tutorial gets this wrong.

**4. Generics — current syntax.** `list[str]`, `dict[str, float]`, `tuple[float, float]` (builtins since 3.9). Stale: `from typing import List, Dict` → `List[str]`. The type *parameter* is what makes Pydantic validation deep + OpenAPI schema precise.

**5. `Protocol` (PEP 544) — net-new.** Structural / static duck typing: a class satisfies a Protocol by *having the shape*, no inheritance/import/registration. Types "anything with a `.read()`" across classes you don't own (stdlib, boto3, vendor SDKs).
- Why over ABC: ABC needs `class X(Base)` — can't do that to a vendor class; Protocol matches by shape.
- Why over no-hint duck typing: keeps flexibility + adds static checking.
- Failure mode: `isinstance` needs `@runtime_checkable`, and even then only checks the method *exists*, not its signature.
