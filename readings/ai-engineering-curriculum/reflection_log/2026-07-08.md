## Taught (current pattern only)
1. **`system` is a SEPARATE top-level parameter**, not `messages[0]`. `messages` holds ONLY user/assistant turns. His one real gap — he'd mentally filed system as messages[0]. Corrected with the caching angle: render order is `tools → system → messages`, so a frozen system prompt is a **cacheable prefix**; the volatile user turns fall after the cache line. This is why the big stable prompt in autoclip/CFO Agent goes in the top-level `system` field.
2. **Assistant turns = the model's own prior outputs, re-sent.** That, and nothing server-side, is the entire mechanism of conversational memory. (Confirmed his answer.)
3. **Two limits, two failures.** `max_tokens` → SOFT truncation, `stop_reason="max_tokens"`, no error, possibly mid-sentence. Context window → HARD reject, `stop_reason="model_context_window_exceeded"` (ties back to §1.1's hard-reject). Load-bearing habit: **always check `stop_reason`.** Resolved his uncertainty cleanly.
4. **⚠ Currency call-out — prefilling is DEAD on Claude 4.6+.** The old "start the assistant turn yourself to force JSON" trick now returns a **400** on claude-opus-4-8/4.7/4.8/Fable 5. Current replacement: **Structured Outputs** — `output_config={"format":{"type":"json_schema","schema":{...}}}`. Why THIS over THAT: structured outputs *enforce/validate* the shape server-side; prefill only *nudged* and could drift. Directly relevant to CFO Agent / Cognizant extraction work.

**Deprecated → current, made explicit:** assistant-turn prefill (course) → `output_config.format` structured outputs (current, 4.6+).
