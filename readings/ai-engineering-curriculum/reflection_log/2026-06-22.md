### Taught (current pattern, live-researched)
1. **The call is STATELESS** — the model has zero memory between calls; the "conversation" is re-sent in full every turn and flattened to one token string. API = pure function `f(all_text) → next_token`, looped to a stop token. This is *why* memory needs a checkpointer, why long agent loops cost more each turn, why context engineering exists.
2. **Token rule of thumb** — ~4 chars ≈ 0.75 words/token; tokens ≈ words × 1.33. Gotchas: tokenizers differ per model; **Opus 4.7's new tokenizer produces ~30% more tokens for the same text** than older Claude (a real stale-estimate trap).
3. **Context window = input + output combined.** Two distinct failures: **hard** = over-limit → API `400` rejection (NOT silent hallucination); **soft** = lost-in-the-middle attention degradation within a legal-but-huge context. Over-limit → chunking/RAG; degradation → better retrieval/ordering. Different cause, different fix.
4. **Cost = (in_tok × in_price) + (out_tok × out_price); output ~5× input price.** Why: input is one parallel forward pass; output is serial autoregressive (one forward pass per token, can't parallelize). Levers: model-by-complexity (Haiku $1/$5 → Opus $5/$25, a 5× spread), prompt caching (claws back the stateless re-send cost), cap `max_tokens` (output/runaway guard only — NOT a quality fix; too-low → mid-answer truncation, `stop_reason: max_tokens`), Batch API (~50% off, async/offline jobs).
