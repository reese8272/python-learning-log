## The ownership block — right slot, wrong verb

"Go over the project file by file and reason it out" is passive review wearing a hard hat. The 12:00 block is the correct 30 minutes; the activity has to force **generation before exposure**:

1. Pick one file. **Don't open it.** Say what it does and why it exists — out loud or typed, it has to leave your head.
2. Open it. Find **one** non-obvious decision — a parameter, a decorator, a config value, an ordering.
3. Answer only: **what breaks if this is wrong, removed, or set differently?** Can't name a failure → you don't own that line yet. That's the finding, not a failure of the block.
4. **Verify live** against current docs. Never from memory.
5. One line in the log: file · decision · failure mode.

One file, one decision, one failure mode. Counts as a floor touch *and* a `/sharpen` rep.
